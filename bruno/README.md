# Bruno API collection

Requests for exploring the sportlab API by hand with [Bruno](https://www.usebruno.com/) (MIT licence). The collection is plain files in the repository, in the OpenCollection YAML format (Bruno 3.0 and later), so it is reviewed in pull requests like code.

Bruno is for manual exploration. The automated API tests are the pytest suite in `backend/tests`.

## Layout

```
bruno/
  opencollection.yml      collection root (name, default environment)
  environments/
    Local.yml             baseUrl for the backend on your machine
  health/                 one folder per API router
    folder.yml
    health.yml            GET /api/health
    health-db.yml         GET /api/health/db
  docs/                   documentation routes generated by FastAPI
    folder.yml
    openapi.yml           GET /openapi.json (the specification)
    swagger-ui.yml        GET /docs (interactive, best in a browser)
    redoc.yml             GET /redoc (read-only, best in a browser)
  auth/                   Google sign-in and the session
    google-login.yml      GET /api/auth/google/login (redirect to Google)
    me.yml                GET /api/auth/me
    refresh.yml           POST /api/auth/refresh
    logout.yml            POST /api/auth/logout
  admin/                  user administration (admins only)
    list-users.yml        GET /api/admin/users
    approve.yml           POST /api/admin/users/:user_id/approve
    disable.yml           POST /api/admin/users/:user_id/disable
    set-role.yml          POST /api/admin/users/:user_id/role
```

The Google callback (`/api/auth/google/callback`) has no request: only Google calls it, at the end of the browser redirect, and it is left out of the OpenAPI specification.

## Setup

1. Start the backend (see `backend/README.md`), for example:

   ```sh
   cd backend
   uv run uvicorn app.main:app --reload
   ```

   `GET /api/health/db` also needs a reachable PostgreSQL at `DATABASE_URL`.

2. In Bruno: **Open Collection** and choose this `bruno/` folder. Bruno reads and writes the files in place; there is no import step.
3. Select the **Local** environment (top right) if it is not already selected.
4. Open a request and send it. The status assertion shows in the **Tests** tab of the response.

To run the whole collection from the terminal with the Bruno CLI (`npm install -g @usebruno/cli`):

```sh
cd bruno
bru run --env Local
```

## Request format

Requests are `.yml` files with `info`, `http`, `runtime.assertions`, `settings` and `docs`. A request without authentication has no `auth` field at all: in this format `auth` is either `inherit` or an object such as `{ type: bearer, ... }`, and `auth: none` is rejected.

## Secrets

Never write a token, cookie, password or key into these files. A value Bruno must send goes into an environment variable marked as **secret**, or into its cookie manager: both stay on your machine, outside the repository.

## Using a browser session

Sign-in needs a browser (Google's pages), so Bruno borrows the session the browser opened. The session is two HttpOnly cookies, `sportlab_access` (15 minutes) and `sportlab_refresh` (path `/api/auth`).

1. Configure Google sign-in (see `docs/google-oauth.md`) and sign in at http://localhost:8000/api/auth/google/login.
2. In the browser's developer tools (**Application** or **Storage** → **Cookies** → `http://localhost:8000`) copy the value of `sportlab_access`.
3. In Bruno, open the **Cookies** manager and add `sportlab_access` with that value for the domain **`127.0.0.1`**, path `/`. The domain must match `baseUrl` in the Local environment, not the `localhost` used by the browser: cookies are kept per host name.
4. Send `auth/Me`: `200` with your account. Admin requests also need the `X-Requested-With` header, already set on them.

After 15 minutes the access cookie expires and requests answer `401`: sign in again in the browser and copy the new value (there is no frontend yet to renew it in the browser).

To renew from Bruno with `auth/Refresh`, copy `sportlab_refresh` as well (domain `127.0.0.1`, path `/api/auth`), then **stop using that session in the browser**. Refresh tokens are single-use: when Bruno refreshes, the browser's copy becomes an old token, and presenting an old token is treated as theft and ends the session for both. Sign in again in the browser when you need it there.

Treat copied cookies like a password: they are a live session. Logout (`auth/Logout`) ends it.

## Keeping the collection in sync with the API

The source of truth is the API itself: FastAPI publishes its OpenAPI specification at `/openapi.json` (and the interactive docs at `/docs`).

`backend/tests/test_bruno_collection.py` compares that specification with the requests in this folder. The test suite, and therefore CI, fails when:

- an endpoint has no request here: add one;
- a request points to an endpoint that no longer exists: update or remove it.

FastAPI leaves its own documentation routes (`/openapi.json`, `/docs`, `/redoc`) out of the specification; the test reads their paths from the application and expects them in `docs/`.

So every pull request that adds, renames or removes an endpoint also updates this folder.

### Adding a request

- **In Bruno:** right-click the router's folder, **New Request**, fill in method and URL as `{{baseUrl}}/api/...`, then save. Bruno writes a new `.yml` file in the folder; commit it.
- **By hand:** copy an existing request file and change `info.name`, `info.seq`, `http.method`, `http.url` and `docs`.
- Path parameters use Bruno's `:name` form (`{{baseUrl}}/api/activities/:id`); the test matches them to OpenAPI's `{id}`.
- A new router gets a new folder with its own `folder.yml`.

### Bulk refresh from OpenAPI (optional)

When many endpoints change at once, Bruno can read the specification instead of writing requests one by one:

- **OpenAPI Sync (beta, in the app):** collection `···` menu, **OpenAPI**, add the URL `http://127.0.0.1:8000/openapi.json`, **Connect**. Sync keeps scripts, tests and assertions and asks when the spec and your edits conflict. The free edition allows a limited number of syncs per month. It saves the spec under `resources/spec/`; review that folder before committing it.
- **Bruno CLI** (`@usebruno/cli`, MIT): `bru import openapi --source http://127.0.0.1:8000/openapi.json --output <empty folder> --collection-name sportlab` generates a brand new collection. It does not merge into this one, so use it in a scratch folder and copy over only the new requests.

In both cases, run `uv run pytest` afterwards: the sync test confirms that the collection matches the API.
